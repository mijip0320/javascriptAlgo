# 80. Remove Duplicates from Sorted Array II

- 학습 날짜: 2026-08-02
- 문제: [LeetCode 80. Remove Duplicates from Sorted Array II](https://leetcode.com/problems/remove-duplicates-from-sorted-array-ii/?envType=study-plan-v2&envId=top-interview-150)
- 언어: JavaScript
- 힌트 단계: 1 (오류 원인과 반환값 조건 확인)

## 문제 핵심

오름차순으로 정렬된 배열 `nums`에서 같은 값이 최대 두 번만 남도록 원본 배열의 앞부분을 수정하고, 유효한 원소의 개수 `k`를 반환하는 문제다. 함수 실행 후에는 배열 전체가 아니라 `nums[0]`부터 `nums[k - 1]`까지만 정답으로 검사된다.

## 예시

```js
nums = [1, 1, 1, 2, 2, 3];
```

결과:

```js
k = 5;
nums의 앞 k개 = [1, 1, 2, 2, 3];
```

## 주요 매개변수와 조건

- `nums`: 오름차순으로 정렬되어 있으며 직접 변경해야 하는 원본 배열
- `expectedNums`: 현재 풀이에서 각 값을 최대 두 번 저장하는 임시 배열
- `k`: 조건을 만족하도록 남긴 원소의 개수
- 유효 범위: 함수 실행 후 `nums[0]`부터 `nums[k - 1]`까지
- 주의할 제약: 결과 배열 자체가 아니라 유효 길이 `k`를 반환해야 하며, `k` 이후의 값은 검사 대상이 아니다.

## 오늘 이해한 핵심 개념

### 1. 빈 배열을 초기화하지 못하게 만드는 조건

처음 작성한 조건에는 `expectedNums.length > 0`이 포함되어 있었다. 그러나 `expectedNums`는 빈 배열로 시작하므로 첫 반복부터 이 조건이 `false`가 된다. 한 번도 값이 추가되지 않아 이후 반복에서도 길이는 계속 `0`이며, 결과적으로 모든 `push()`가 막힌다.

각 값의 저장 여부를 판단하는 실제 기준은 해당 값이 `expectedNums`에 이미 몇 번 들어 있는지다. 등장 횟수가 `2`보다 작을 때만 추가하면 한 값당 최대 두 번까지 저장된다.

### 2. 반환값 `k`와 배열의 유효 구간

처음에는 수정한 `nums` 배열 전체를 반환했지만, 이 문제의 반환값은 배열이 아니라 정수 `k`다. 임시 배열의 값을 `nums` 앞부분에 복사한 뒤 `expectedNums.length`를 반환해야 한다.

예를 들어 수정 후 `nums`가 다음과 같아도:

```js
[1, 1, 2, 2, 3, 3]
```

`k`가 `5`이면 앞의 다섯 값인 `[1, 1, 2, 2, 3]`만 유효하다. 뒤에 남은 값은 삭제할 필요가 없다.

## 풀이 흐름

```text
빈 임시 배열 준비
→ nums를 순회하며 현재 값이 임시 배열에 두 번 미만 존재하는지 확인
→ 조건을 만족하면 임시 배열에 추가
→ 임시 배열의 값을 nums 앞부분에 복사
→ 임시 배열의 길이를 k로 반환
```

현재 작성한 풀이가 어떻게 동작하는지를 정리한 흐름이다. 정렬 조건을 활용하면 별도의 배열과 반복적인 전체 검색 없이 개선할 수 있다.

## 사용한 메서드·자료구조 비교

| 항목 | 반환값/동작 | 원본 변경 여부 | 사용 이유·주의점 |
|---|---|---:|---|
| `filter()` | 조건을 만족하는 원소로 만든 새 배열 | X | 현재 값의 저장 횟수를 구하지만 매 반복마다 임시 배열을 다시 순회한다. |
| `push()` | 추가 후 배열 길이 | O | 등장 횟수가 두 번 미만인 값을 임시 배열에 추가한다. |
| 인덱스 대입 | `nums[j]`의 값 변경 | O | 임시 배열의 결과를 원본 배열 앞부분에 반영한다. |
| `length` | 배열의 원소 개수 | X | 유효한 결과의 개수 `k`로 사용한다. |

## 더 효율적인 권장 접근

- 알고리즘: 투 포인터
- 시간 복잡도: `O(n)`
- 공간 복잡도: `O(1)`
- 핵심 아이디어: 배열이 정렬되어 있으므로 쓰기 위치보다 두 칸 앞의 값과 현재 값을 비교하면, 현재 값을 추가해도 같은 값이 세 번 연속 저장되는지 판단할 수 있다.

현재 `filter()` 기반 풀이의 시간 복잡도는 최악의 경우 `O(n²)`이고, 임시 배열 때문에 공간 복잡도는 `O(n)`이다. 각 반복에서 `filter()`가 지금까지 저장된 원소들을 다시 확인하기 때문이다.

## 오늘 발견한 실수와 교정

### 1. 빈 배열에 첫 값을 넣지 못하는 선행 조건

- 시도한 코드·생각: `expectedNums.length > 0`일 때만 중복 횟수를 검사하고 값을 추가했다.
- 왜 틀렸는가: 빈 배열에서는 조건이 처음부터 거짓이고, 값이 추가되지 않으므로 영원히 거짓으로 남는다.
- 올바른 기준: 현재 값이 이미 저장된 횟수가 `2`보다 작은지만 확인한다.
- 다음 체크: 누적 결과 배열을 조건에 사용할 때 첫 번째 원소가 실제로 들어갈 수 있는지 손으로 추적한다.

### 2. 반환해야 하는 대상을 배열로 오해

- 시도한 코드·생각: 원본 배열을 수정한 뒤 `nums`를 반환했다.
- 왜 틀렸는가: LeetCode의 judge는 반환값을 유효한 원소 개수 `k`로 사용한다.
- 올바른 기준: 원본 배열의 앞 `k`개를 수정하고 정수 `k`를 반환한다.
- 다음 체크: 구현 전에 반환 대상이 값, 배열, 인덱스, 개수 중 무엇인지 먼저 확인한다.

## 복습 질문

- 현재 풀이에서 `filter()`를 반복하면 시간 복잡도가 왜 `O(n²)`이 되는가?

- 빈 배열, 원소가 하나뿐인 배열, 모든 값이 같은 배열에서는 각각 어떤 `k`가 반환되어야 하는가?
